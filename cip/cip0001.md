# CIP-0001: Theme, Pages workflow, and Decap admin

## Status

- [x] Proposed
- [x] Accepted
- [x] In Progress
- [ ] Implemented
- [ ] Closed

## Summary

Point year sites at `lawrennd/jekyll-theme` rather than the personal
`cabrerac/jekyll-theme-sorrento` fork. Fix giki edit links and the Pages
workflow for `main`-branch repos. Add a Decap admin in the year site, not in
the theme.

## Motivation

The 2026 site consumed Christian Cabrera's fork of the shared theme. That fork
is the wrong long-term home for a recurring meeting. New year repos use `main`,
but edit links and the GitHub Actions workflow still assumed `gh-pages`.
Workshop organisers also need a way to edit programme YAML without hand-editing
posts; Decap belongs in the year repository.

This is conference chrome, not the Fenner publication/CiteProc layer. Fenner
does not block 2027.

## Implementation

1. Bring remaining Sorrento chrome from the Cabrera fork into
   `lawrennd/jekyll-theme` (organiser lines, `affiliation` on people).
2. Add `ghub.branch` so giki edit links work on `main`.
3. Dispatch `head.html` through the existing `style:` include so Sorrento pages
   do not inherit the ML@CL document head.
4. Set `remote_theme: lawrennd/jekyll-theme` in the template and 2027 site.
5. Run the Pages workflow on `main` and `gh-pages`.
6. Add `admin/` (Decap CMS) to the template and 2027 site.
